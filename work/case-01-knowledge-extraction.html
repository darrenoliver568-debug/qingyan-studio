AI 明明读对了，为什么还是会写错？ E02 · Same Source → Same Output File → Inconsistent Fidelity

AI 不是没读懂，而是把课程事实擅自优化成了它认为更合理的做法。

BEAT 03 Controlled Fix

怎么修？只改真正失败的地方 E04 · 修复不是推倒重写，而是唯一追加一段强约束

原 Prompt 已经有「不要编造、必须回查原文」等规则。但它没挡住这个问题：

AI 会把课程实际操作自动升级成「最佳实践」。

所以没有重写 Prompt，只新增针对性约束：

课程没明确说是最佳实践，就不能写成最佳实践。

BEAT 05 Escalation

AI 不确定的时候，什么时候应该停下来交给人？ E08 · Two-Key Rule · Human Review Queue

AI 自动确认术语时，必须同时满足两个条件，否则必须停下来交给人。

Two-Key Rule
Key-1 标准术语存在于 Transcript
Key-2 当前表达与标准术语之间有直接证据

AI 必须停止自动确认。

MY DECISION

发现更多问题，不等于应该继续设计更复杂的 Schema。

Open Questions

  • Human 与 Two-Key 的权限边界
  • 无视频资产造成的 Evidence Ceiling
  • SRT 只能表示本地录音时间
  • Human Review 有真实时间成本

Open Issue ≠ Schema Failure

我最终学到的不是「怎么让 AI 更会总结」

而是：

  • AI 什么时候可以确认
  • AI 什么时候必须停止
  • 谁拥有最终验收权
  • 一个修复凭什么算有效
工程方法 Failure → Diagnosis → Fix → Validation → Escalation
以及 模型提出质疑 → 回原始证据 → 最低成本实验 → 再决策

目标不是让 AI 永远给答案，而是让系统知道什么时候不该相信自己。
